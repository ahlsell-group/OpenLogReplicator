As `big-txn-olr-restart-fresh`, our deployment's restart mode (the init step deletes the writer checkpoint, so every OLR start answers READY and the task sends START at its offset SCN), done twice inside one 40000-row transaction. The second START comes after the task has delivered and flushed more of the transaction on the first restart's stream, so its offset index was numbered by the restarted OLR: positions must be the same in every run. OLR reads redo from a schema checkpoint whose stream position was below the start SCN (`state_interval_s` 2 writes them often).
