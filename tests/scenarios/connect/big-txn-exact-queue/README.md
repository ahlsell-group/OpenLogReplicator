OLR's network writer runs with queue-size 2000 and one transaction inserts exactly 2000 rows. With its BEGIN and COMMIT that is 2002 messages, two more than the queue: Debezium 3.7.0.Final and 3.7.0.Final-ahlsell.11, which confirm (offset scn, 0), stall with WARN 60040 (known issue). With `openlogreplicator.confirm.within.transactions` the transaction is released as its offsets are flushed. The boundary case of `big-txn-queue`.
