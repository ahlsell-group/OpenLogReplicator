The cold-start boundary case (txn/cold-start-mid-transaction) through real Debezium: first start of the connector (snapshot.mode=no_data, OLR state empty) while a transaction that began two log switches earlier is still open; it commits after START. Debezium sends START(snapshot SCN) without index, so skipToStartScn drops every event whose scn < START. Expected: the long transaction's rows (before and after START) arrive at least once (duplicates are reported in the delivery check, not failed), the transaction committed before START does not arrive (it is in the snapshot or before the stream).
