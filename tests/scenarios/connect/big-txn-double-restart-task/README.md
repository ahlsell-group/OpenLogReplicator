One transaction inserts 40000 rows with queue-size 2000. The task is restarted over REST once 6 000 rows are on the topic and again after 8 000 more, both times inside the transaction. Each restart continues after the position OLR reports confirmed (CONTINUE with c_idx > 0); the second one starts from an offset written after the first replay, so a replay that moved the offset back or restarted the transaction's counters would show as duplicates or a wrong END `event_count`.
